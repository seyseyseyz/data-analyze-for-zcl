# 自适应报告领域架构 — 设计规格

**日期：** 2026-08-02
**状态：** Approved
**目标：** 保留稳定的核心经营结构，同时让投流等新增数据自动获得足够深的独立分析空间，不再被塞进既有大类。

## 1. 问题

现有事实层报告把分析模块归入 6 个固定领域。这个结构便于阅读，但“流量与内容”同时容纳自然流量、搜索、内容表现、重拍机会和投流效率，已经承担过多职责。

领域数量本身不能证明数据挖掘充分。完整性应由“每项可用数据是否产生分析结果或明确阻断原因”保证，而不是靠继续扩充固定目录。

## 2. 决策

采用“6 个核心领域 + 数据激活领域”：

1. 核心领域保持稳定：生意大盘、流量与内容、商品结构、用户与需求、退款与售后、实验与下周行动。
2. `paid_traffic_efficiency` 从“流量与内容”迁入独立的“付费增长”领域。
3. 数据激活领域只在对应分析结果包含观测数据行时出现。
4. 有投流数据但字段较弱时仍显示“付费增长”，并保留弱证据、限制和补数建议；不能因为数据不理想而隐藏已上传数据。
5. 完全没有投流数据时不显示空的“付费增长”领域；`ad_data_quality_check` 继续在数据质量附录中透明说明缺表或缺字段。
6. 未注册的新任务仍进入“其他参考”，防止新增模块被静默丢弃。

## 3. 激活语义

“包含观测数据行”定义为：领域内至少一个 `AnalysisResult.tables` 表含有一行或以上数据。

该规则有意不把 ROAS、GMV 或点击设为领域出现的硬门槛：

- 只有消耗和曝光的数据仍然是已发生的投放事实，应在“付费增长”中显示，但必须标成弱证据或待补数据。
- 没有任何数据行的不可判断结果不创建空领域，避免报告出现只有标题的章节。
- 是否允许增投、减投或作因果判断，继续由分析模块的证据和限制控制，不由领域注册表越权判断。

## 4. 报告职责

- 决策简报负责排序和索引，不删除领域分析。
- 事实层保留所有已激活领域的完整模块、发现、图表、明细、限制和方法说明。
- 每个领域默认展示核心模块，其余模块在同一 HTML 中折叠，不拆成外部文件。
- 报告导语说明结构是“核心领域 + 按数据扩展”，不再声称永远只有 6 个领域。

## 5. 本期范围

本期实现：

- 自适应领域注册与激活规则。
- “付费增长”独立一级领域。
- Markdown、HTML 和技能内置副本行为一致。
- 回归测试覆盖有数据、无数据、弱数据和未知任务兜底。

本期不实现：

- 新的投流漏斗、边际 ROAS、预算饱和、增量归因算法。
- 库存、利润、直播或达人合作领域。
- 基于文件名猜测领域；领域只能由标准化分析结果激活。

## 6. 验收标准

1. `paid_traffic_efficiency` 只归入“付费增长”，不再出现在“流量与内容”。
2. 含非空投流表的结果同时在 Markdown 和 HTML 中生成“付费增长”。
3. 投流表为空时不生成空领域，也不落入“其他参考”。
4. 弱投流数据只要含观测行仍激活领域，其限制保持可见。
5. 所有注册任务仍恰好归入一个领域或附录。
6. 源码与 `skills/data-analyze-for-zcl/assets/xhs-ca` 内置副本一致。
