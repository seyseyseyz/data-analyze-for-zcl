# 单次授权与必要人工判断 — 设计规格

**日期：** 2026-08-02  
**状态：** 待确认  
**目标：** 一份报告只确认一次多智能体授权；流程中断或并发额度不足时自动续跑，只有必须由业务人员裁决的字段或指标口径问题才再次询问。

## 1. 授权规则

1. 用户对本次报告确认多智能体授权后，该授权覆盖后续全部叙事阶段、重试和恢复。
2. 同一 `run_id` 且冻结的 `facts_hash` 未变化时，不得再次询问多智能体授权。
3. 普通进度、阶段切换、运行中断、工具超时和并发额度不足都不是重新授权理由。
4. 用户拒绝授权、新建另一份报告，或事实快照发生实质变化时，才重新判断授权状态。

## 2. 并发额度处理

当派发子智能体遇到并发额度不足时，按以下最小流程处理：

1. 检查已经派发的子智能体状态。
2. 摄取已完成子智能体的结果，并关闭这些已结束的子智能体以释放额度。
3. 重新派发仍处于 pending 的任务；必要时减少同时派发数量，允许串行完成。
4. 并发额度不足只属于临时调度问题，不触发确定性骨架版、不标记 `unsupported`，也不要求用户继续或重新授权。

不新增复杂队列、后台 worker 或新的业务状态机；沿用现有 durable task queue 和 `status --json` 控制循环。

## 3. 人工判断边界

只有无法从当前数据、已批准字段绑定和平台口径目录中安全确定的业务语义，才请求人工判断，例如：

- 一个源字段可能对应多个规范字段；
- 支付时间与退款时间口径无法确定；
- PV 与 UV、金额与比例、日级与期间去重口径存在冲突；
- 候选映射会实质改变指标或报告结论。

缺少数据、弱证据、普通任务被阻断或可使用中性默认值时，不询问用户；分别采用 `Not-judgable`、补数建议或中性命名继续执行。

## 4. 人工判断信息要求

每次必须人工判断时，一次性提供足够信息：

1. 原始文件、工作表、源字段名及代表性样例值；
2. 候选规范字段及其官方定义；
3. 单位、粒度、聚合方式、PV/UV、支付/退款时间等口径差异；
4. 当前映射审计状态、匹配方法、匹配分数和冲突原因；
5. 接受各候选项分别影响哪些任务、指标和报告结论；
6. 推荐选项及推荐理由，同时允许用户选择“不映射并继续”。

不得只问“这个字段怎么映射”或只给候选名称。

## 5. 验收标准

1. 同一报告授权后跨阶段、跨回合恢复时不再询问授权。
2. 模拟并发额度不足时，先关闭已结束子智能体，再完成剩余任务。
3. 并发额度不足不会进入确定性 fallback 或 `unsupported`。
4. 缺字段但无需语义裁决时，报告以不可判断和补数建议继续完成。
5. 必须人工裁决时，问题包含第 4 节的全部判断信息。
6. 源码技能、runbook 与安装包副本保持同步。
